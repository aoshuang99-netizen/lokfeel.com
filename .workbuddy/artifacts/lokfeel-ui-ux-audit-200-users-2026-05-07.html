Executive Summary

The Dateasy Dark theme migration (v4 warm-sand → v5 dark-purple) is ~92% complete. While CSS variables and most components are properly themed, several critical areas still contain hardcoded light-theme colors that create visual inconsistency in a dark-first application.

Most impacted areas: Onboarding Tour tooltip (12 light-theme classes), Onboarding step selectors (bg-white text-black), and scattered gray-* utility classes across chat/square/matches components.

Key finding: The onboarding-tour.tsx component renders as a fully light-themed floating tooltip on top of the dark UI — creating an extremely jarring visual clash for new users during their first experience.

P0 — Critical: Broken/Unusable

3 issues
P0 DarkTheme
Onboarding Tour tooltip is entirely light-themed on dark UI
src/components/onboarding/onboarding-tour.tsx:312-385
The onboarding tour renders a white card (bg-white) with light text colors (text-gray-900, text-gray-500), light borders (border-gray-100), and light backgrounds (bg-gray-100, bg-gray-200) — 12 hardcoded light-theme classes total. This creates an extreme visual clash for new users experiencing the product for the first time.
Replace: bg-white→bg-background-secondary, text-gray-900→text-foreground, text-gray-500→text-foreground-muted, border-gray-100→border-card-border, bg-gray-100→bg-background-tertiary, bg-gray-200→bg-background-tertiary
Impact: First-time user experience is severely degraded. The tour tooltip looks completely disconnected from the app.
P0 DarkTheme
Onboarding step selectors use bg-white text-black on dark background
src/app/(dashboard)/dashboard/onboarding/page.tsx:1092,1488
Active selection cards in onboarding (Step 3 photos, Step 8 completion) use "bg-white text-black" as the selected state. On the dark #0a0a0a background, these appear as glaring white rectangles — functionally correct but visually inconsistent and jarring.
Replace selected state: "bg-white text-black" → "bg-primary text-white" or "bg-accent-lime text-black" for the Dateasy theme's selection indicator.
Impact: Every new user sees these during onboarding — the most critical UX journey.
P0 Interaction
Chat input has no image/attachment upload button wired to upload logic
src/components/chat/chat-input.tsx:5 (Image icon imported but not functional)
The chat-input imports the Image icon from lucide-react but there is no file input, FormData upload, or API call for sending images in chat. The Image button appears to be a dead UI element. Users expect to be able to share photos in a dating app chat.
Add a hidden file input, wire Image icon click to trigger it, create FormData with the selected image, POST to /api/chat/[roomId]/messages with type IMAGE.
Impact: Core dating app functionality missing. Users cannot share photos in chat — a critical feature for any dating platform.
