## 1. 交付物：一条命令

```bash
node scripts/qa/prod-smoke.mjs --commit=<发布 SHA> --json=reports/smoke/post-<SHA>.json
```

- **只读**：全部 GET；唯一的两个 POST 是"取消订阅"和"结账"，都是**必须被拒绝**的调用，且不带凭据。
- **三态**：`PASS / FAIL / UNVERIFIED`。取不到就写 UNVERIFIED，不写 PASS。
- 退出码 = FAIL 的数量（0 即全过）。
- 覆盖：Runbook §4 五项 + WB18-32 要求的十项回归 + 本轮新增的认证页缓存判据（共 **15 条**）。

**这 6 条红不是缺陷，是"版本差"。** 它们恰好是 6 个可观测的症状，发布后应当**同时**变绿：

| 编号 | 发布前 | 发布后应为 |
|---|---|---|
| `R1` | 无 `commit` 字段 | `commit == 0507434` |
| `R2` | 307 → Hlua 页 | 200 |
| `R3` | `/hlua` 404 | 200 |
| `R4` | 404（路由不存在） | 401（路由存在但拒绝匿名） |

> 这就是"一条命令证明版本真的换了"：6 个独立判据同时翻转，
> 比单看 `/api/health` 的 200 强得多 —— 200 在坏发布时也成立。

### 3.1 一个顺带确认的事实

`G10` 实测结账端点在匿名时返回 **401**（不是 503）。
说明它**先校验身份、再校验支付配置**。两种都是合格形态（都不会产生订单），
这条写在这里，免得以后有人看到"不是 503"就以为支付被打开了。

## 6. 为什么这份文档没有"通过"二字

任务书要求"五项全部 PASS"。现在的事实是：**这五项对应的判据有 3 项在发布前必然为红**，
因为生产跑的是旧代码。写"PASS"只有一种可能 —— 造假。

所以这里的交付是：**判据可执行、基线已采、一条命令可复现**。
`D-10` 一旦批准，本文第 3 节的表就是对照表，第 4 节就是要填的记录。
