# T02 · risks — 风险清单

> 按「未消除 / 已规避 / 已发生 / 需决策」四类。**未消除的风险不假装消除。**
> T02 建立了本仓**第一个匿名可达面**（`/m/[token]` 与 `/api/v1/public/...`），风险重心随之从"迁移安全"转到"公开暴露面"。

---

## 1. 未消除的风险（需知晓）

### R1 🔴 分享页是匿名可达面，而 **令牌即能力凭证**（可转发、可爬取）

| 项 | 说明 |
|---|---|
| 现状 | `/m/<shareToken>` 不要求登录即可预览；**持有链接的人就能看到全部公开字段** |
| 原因 | 「免安装分享」的产品形态使然 —— 这是需求，不是缺陷 |
| 影响 | ① 链接被转发到社群外 ② 爬虫批量抓取公开任务 ③ 令牌泄露后**无法在 URL 层撤销** |
| 缓解 | 高熵令牌（24B CSPRNG，不可枚举）+ 形状预检（非法形状不触达 DB）+ 限流 + `Cache-Control: no-store` + **白名单投影**（内部标识与 `constraints` 一律不出现在响应）+ `publicPreview` 可关闭 + `pause`/`close` 可**即时**终止分享 |
| 消除路径 | T05/T10：令牌轮换（rotate）与访问审计；当前仅靠"关闭/暂停"这一粗粒度开关 |

### R2 🟠 限流在 Redis 未配置时是**进程内计数**，serverless 下形同弱防护

| 项 | 说明 |
|---|---|
| 现状 | `rateLimit({ windowMs: 5*60*1000, max: 120 })`；Redis 不可用时退化为进程内计数 |
| 影响 | 多实例/冷启动场景下实际放行量可能远大于 120/5min → **防不住有意的批量探测** |
| 缓解 | 令牌不可枚举（形状预检 + 高熵）使"猜令牌"本就不可行；限流只是纵深防御的一层 |
| 消除路径 | 配置 `UPSTASH_REDIS_REST_URL/TOKEN`（代码无需改动）→ 见 `docs/IM-REDIS-DEGRADATION.md` |

### R3 🔴 隔离仍是**应用级**（承接 T01 R1），分享页跨租户读取全靠谓词

| 项 | 说明 |
|---|---|
| 现状 | `getSharePageData()` 以 `shareToken` 唯一定位，再由返回的 `organizationId` 校验租户与 `Organization.status`；无 DB 级 RLS |
| 影响 | 若将来有人改写查询而漏掉租户/状态谓词，DB 不会拦住 |
| 缓解 | 单测含「跨租户查询与写入拒绝」+ 「查询谓词必须含 organizationId」防回归锁 |
| 消除路径 | M6（PG + RLS） |

### R4 🟠 `candidates: never[]` 是**类型级**铁律保证，T04 引入真实候选时必须同步改造

| 项 | 说明 |
|---|---|
| 现状 | `toPublicMissionView()` 把 `candidates` 声明为 `never[]`、`candidatesAvailable: false` → **编译期**就写不出伪造候选的渲染 |
| 影响 | ⚠️ 这是"善意的紧约束"，T04 一旦返回真实候选，**必须同时**修改投影、页面分支与 E2E 断言；若只改一半，可能出现"类型放宽了但投影仍泄露内部排序依据" |
| 缓解 | 已在 `changes.md` §6 与本节显式登记；T04 开工前先读此条 |
| 消除路径 | T04（此时 `candidates` 改为真实类型，并补"每个候选必须有可解释依据"的断言） |

### R5 🟡 加入是"先到先得"，无公平性/候补机制

| 项 | 说明 |
|---|---|
| 现状 | 名额竞态用"写入后超额 → 补偿 WITHDRAWN + 409"处理，语义是**先到先得** |
| 影响 | 高热任务上晚到者永远失败；无候补队列、无通知 |
| 消除路径 | T07（Console 侧名额管理与通知）/ T08（漏斗指标） |

### R6 🟡 `IdempotencyRecord` 无 TTL / 无清理策略，会随写操作单调增长

| 项 | 说明 |
|---|---|
| 现状 | 每次带键的写操作落一行；无过期、无归档 |
| 影响 | 长期看是"只增不减"的表；且 `requestHash` 会长期保留请求指纹 |
| 消除路径 | **AC-10（数据生命周期）** —— 该条在 T00–T12 中目前无人认领（见 `BACKLOG.md` §5①，建议挂 T05） |

## 2. 已消除 / 已规避的风险

### R7 ✅ 迁移破坏既有结构 → 已规避（纯新增）

C0 只 `CREATE TABLE/INDEX IF NOT EXISTS`，**不改动既有 48 张表的任何列**。生产实测：迁移后 `/api/health` 200。

### R8 ✅ 迁移不可重跑 → 已规避

全部语句带 `IF NOT EXISTS`；重跑 `apply` 全部为空操作。生产与本地夹具库均复现。

### R9 ✅ `prisma db push` 对远程 Turso 失败（P1013）→ 已规避

迁移走 `@libsql/client` 直执行 SQL；`prisma/migrations/` 仅作变更记录（与 T01 同策略）。

### R10 ✅ 分享页被 CDN 长期缓存 → 已规避

端点显式 `Cache-Control: no-store`，且 `region-policy` 的 `getCacheControl` 对 `/m`、`/m/` 强制 `private, no-store`；该策略已写入门禁（`verify:geo` 新增 2 项断言，67 → 69）。

### R11 ✅ dev 冷编译导致的 E2E 假失败 → 已规避

`beforeAll` 预热两条写路由（登录用错误密码、加入用无会话请求，**均不产生副作用**）；断言窗口不再被 7–14s 的现场编译吃掉。首跑/次跑各 7/8，修复后 **8/8**。

## 3. 已发生的缺陷（已修复，留档）

| # | 缺陷 | 发现方式 | 修复 |
|---|---|---|---|
| B1 | 幂等并发**漏回收孤儿资源**（胜者 `requestHash` 不同时） | `idempotency.test.ts` 失败 | 改为**总是先 `compensate` 再判定胜者** |
| B2 | `json-codec` 把对象 JSON 当单元素数组 | `json-codec.test.ts` 失败 | `{` 开头直接返回 `[]` |
| B3 | 🔴 **`verify` 孤儿断言形同虚设**：`countRows()` 漏第 3 个 `where` 形参 → 用全表行数冒充孤儿数（空库假绿 / 非空库假红），引用完整性从未被校验 | 在**非空夹具库**上跑 `verify` 报「孤儿 2 / 孤儿 1」= 总行数 | 补形参 + 注释说明不可删；并用「注入孤儿 → 精确报出 → 清理复原」负向自证（`tests.md` §4） |
| B4 | 分享页 `page.tsx` 渲染 `view.candidates.map(...)` 与 `never[]` 类型冲突 | `tsc --noEmit` | 只渲染空态分支（让类型保证成为设计的一部分） |
| B5 | E2E 加入用例因 hydration 延迟点击静默无效 | 首跑第 8 例失败 | `networkidle` + 容错重试块 |

> B3 是本任务"最值得记"的一处：**校验器本身出错会同时产生假绿与假红**，
> 而它在空库上恰好为真 —— 正是"看起来通过"最容易骗过人的形态。
