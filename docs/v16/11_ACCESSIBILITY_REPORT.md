# 11 · 无障碍报告

> 范围：13 屏（`/workspace` 六屏 + `/console` 七屏）+ 公开首页。
> 方法：**能算的算**（令牌对比度）、**能量的量**（触控目标、reduced-motion、hydration），
> 剩下需要人来判断的（屏幕阅读器朗读顺序、焦点顺序是否合理）标 **UNKNOWN**，不冒充通过。

## 一、对比度（WCAG 2.2 AA）

`npm run verify:contrast` 直接对 `globals.css` 里的令牌做 WCAG 相对亮度计算，
覆盖 **5 个调色板块 × 15 组前景/背景**，共 75 组。

### 首跑抓出的 3 个不达标（已修）

| 令牌 | 背景 | 修前 | 修后 | 阈值 |
|---|---|---|---|---|
| `--lf-text-faint`（深色） | `#171c21` / `#1f262d` | **3.60 : 1** | 5.15 / 4.59 | 4.5 |
| `--lf-text-faint`（浅色） | `#ffffff` / `#efebe3` | **3.16 : 1** | 5.02 / 4.51 | 4.5 |
| `--lf-signal`（浅色） | `#ffffff` / `#f7f5f0` | **3.22 : 1** | 4.94 / 4.53 | 4.5 |

取值：`#868e93`（深色弱化文字）、`#63696d`（浅色弱化文字）、`#906931`（浅色暖金）。

> 这三个都不是"设计觉得差不多"，是算出来的：弱化文字大量用在 10–11px 的标签上，
> 属于正文尺寸，必须 4.5。修复后 75 组全绿，且已进 `npm run verify:contrast` 常态门禁。

## 二、触控目标（44×44）

判据：V16 任务书 §14 的 44×44。WCAG 2.2 的 2.5.8（AA）只要求 24×24，
所以这里比 AA 更严 —— 但**只在 ≤1023px 强制**，桌面保留紧凑密度（鼠标用户不需要 44px）。

| 屏 | 修前（移动端达标/总数） | 修后 |
|---|---|---|
| `/workspace` Now | 12/15 | **15/15** |
| `/workspace` Studio | 12/16 | **16/16** |
| `/workspace` Field | 12/18 | **18/18** |
| `/workspace` Consent | 12/17 | **17/17** |
| `/workspace` Outcomes | 12/15 | **15/15** |
| `/workspace` Agents | 12/15 | **15/15** |
| `/console` 总览 | **0/8** | **8/8** |
| `/console` 任务 | **0/14** | **14/14** |
| `/console` 连接 | **0/15** | **15/15** |
| `/console` 智能体 | **0/13** | **13/13** |
| `/console` 成员 | **0/16** | **16/16** |
| `/console` 成果 | **0/12** | **12/12** |
| `/console` 设置 | **0/8** | **8/8** |

做法分两层：
1. 骨架层显式 `min-h-11`（console 导航 44px、"个人模式" 44px、工作区主题/证据/编译按钮 44px）；
2. 兜底层 `@media (max-width: 1023px)` 对所有 `button/select/input/textarea` 施加 `min-height:44px`
   （`:where()` 0 特异性，显式 `h-*` 仍可覆盖）。

**终跑复核（`a336263`，`audit:release`）：移动端 13/13 屏全部达标（0 个小于 44px 的控件）。**
桌面端仍有 1–8 个小于 44px 的控件 —— 这是**刻意的**：`pointer: fine` 下 44px 会让筛选条与表格变胖，
44×44 是触控目标要求，不是鼠标目标要求。

## 三、动效与降级

| 项 | 结果 |
|---|---|
| `prefers-reduced-motion: reduce` | `main` 的 `transition-duration` 实测 **0s**（`/` 与 `/workspace` 均为 0s） |
| 3D 场景降级 | 走 `data-gate="scene3d"` 的静态分支；`reducedMotion` 命中时 rAF 完全不启动 |
| 图渲染不可用 | `field-fallback.tsx` 提供 2D 列表 |

## 四、语义与键盘

| 项 | 现状 |
|---|---|
| 页面唯一 H1 | `/console` 七屏此前**各有两个 h1**（组织名 + 页面名），组织名恒为同一串 → 已把组织名降为 `<p>`，每屏只剩一个页面级 h1 |
| 阶段条 | `<ol>` + `<button>`，`aria-current="step"` 标当前段；每段 `aria-label` = 段名 + 计数 + 是否当前 |
| 未就绪能力 | 渲染为 `disabled` + 原因，不是空按钮（AC-18） |
| 无权限入口 | 渲染为不可点 `<span>` + 「无权限」，不是死链 |
| 焦点可见 | 统一 `lf-focus-ring` 类 |
| 图标按钮 | 均有 `aria-label`（"切换画布…"、"收起证据面板" 等） |

## 六、UNKNOWN（必须人来测）

| 项 | 为什么不能自动判 |
|---|---|
| 屏幕阅读器实际朗读顺序（VoiceOver / NVDA） | 需要真机朗读；DOM 顺序正确不等于朗读体验正确 |
| 键盘能否独立完成"审批 → 撤销"整链 | 需要人工按 Tab 走一遍；脚本能点但不能判断"是否可达" |
| 3D 画布的等价替代是否"可操作" | 目前只有 2D 降级列表，是否覆盖全部节点需人工核对 |
| 色彩单独表达状态 | 已尽量避免（状态都带文字标签），但未做灰度截图逐屏确认 |
