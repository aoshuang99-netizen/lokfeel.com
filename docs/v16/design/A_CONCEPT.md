# 方案 A · Living Universe（星群）

> 状态：**原型**。未进入生产。可交互预览：`design/preview/A-living-universe.html`
> 评分：综合 **3.55**（详见 `COMPARISON_SCORECARD.md`）

## 一、方向

把工作区当成一片**深空场**：意图从中心点亮，Mission 成为一颗恒星，成员 / Agent / Consent / Outcome
作为可交互节点在轨道上展开。导航不是标签页，而是"视角高度"——拉远看关系，推近看细节。

## 二、原型里真实做了的部分

| 要素 | 做法 |
|---|---|
| 主画布 | 中心 Mission 核 + 3 层轨道（人 / 智能体 / 授权与成果），节点大小映射真实计数 |
| 交互 | 指针视差、节点 hover 提升、点击把节点提到中心并展开其证据链 |
| 状态 | Loading / Empty / Error 三态与真实数据同形（空态不编造星体） |
| 移动端 | 轨道降为纵向列表，保留节点与计数，不保留 3D |
| 降级 | `prefers-reduced-motion` 下停止轨道旋转与视差；WebGL 不可用时退化为静态 SVG |

## 三、为什么不做成生产

1. **信息密度不足**：审批这类高频操作需要"一次看到 8 行待批"，星群一次只能突出 1 个焦点；
2. **移动端成本高**：390×844 下轨道必然退化为列表，3D 的优势在手机上是负资产；
3. **可审计性弱**：节点在动，截图与录屏难以作为"我当时看到什么"的证据；
4. **性能不确定**：目标设备上的帧率必须实测，而审计显示我们还没有性能基线。

## 四、值得吸收的部分（已吸收进方案 C）

- 中心聚焦的"当前任务"感 → 变成阶段条的聚焦段与 Inspector 的标题；
- 节点计数的视觉权重（数字大、标签小）→ 阶段条沿用；
- 深色场的品牌记忆点 → 双世界的左半（Canvas）保留 Deep Field 调色板。
