# 13 · 视觉方案对照

> 三套方案的可交互原型在 `design/preview/`，评分方法见 `design/COMPARISON_SCORECARD.md`。
> 本文回答两件事：**为什么选 C**、**C 落地后屏幕上到底变了什么**。

## 一、三方案加权得分

| 维度（权重） | A 星群 | B 纸张 | C 双世界 |
|---|---|---|---|
| 业务效率 25% | 3.0 | 4.5 | **4.6** |
| 清晰与可理解性 20% | 2.8 | 4.6 | **4.3** |
| 生成式交互创新 20% | 4.8 | 2.6 | **4.2** |
| 视觉辨识度 15% | 4.7 | 3.0 | **4.3** |
| 移动端与无障碍 10% | 2.4 | 4.2 | **4.0** |
| 性能与实现成本 10% | 2.3 | 4.6 | **4.0** |
| **加权** | **3.55** | **4.03** | **4.30** |

C 没有一项拿第一，但**没有一项低于 4.0** —— 这正是"双世界"的用意：
用左半拿 A 的识别度，用右半拿 B 的效率，代价是两边都不极致。

## 二、C 落地后的可见变化（不是描述，是可对照的差异）

| 位置 | 改版前（`screenshots/before/`） | 改版后（`screenshots/after/`） |
|---|---|---|
| `/workspace` 顶部 | 只有 ContextBar（LOKFEEL / My Workspace） | 多一条 **Mission pipeline**：提案 / 同意 / 执行 / 成果 四段 + 真实计数 + 「下一步」一句 |
| `/workspace` 左右 | 全屏同一套明暗 | **左深右浅**：Canvas 是 Deep Field，Inspector 是 Living Paper |
| `/workspace` Now | 三张计数器（含「我的匹配」） | 第三张改「待你介绍」（来自提案端点）；阶段条给出"下一步" |
| `/workspace` Studio 空态 | 只有一句"先在底部输入一个目标" | 多一个 **「开始输入目标」** 按钮，点了直接聚焦输入框 |
| `/workspace` Studio 首段 | "zod 严格校验 / 白名单组件 / 不允许产出 HTML" | "要联系谁、要谁同意、做成什么算完成、结果怎么核验" |
| `/console` 七屏 | 组织名是 h1，七屏 H1 相同 | 组织名降为上下文，页面标题成为唯一 h1 |
| 移动端底部 | 输入框压住最后一屏内容 | 留白按输入框高度 + 安全区计算，内容可完整滚出 |
| 弱化文字 | 深色 3.60:1 / 浅色 3.16:1（不达 AA） | 5.15:1 / 5.02:1 |
| 浅色强调文字 | 3.22:1（不达 AA） | 4.94:1 |

## 三、C 的"自适应"具体是什么（避免被当成动画）

| 机制 | 触发 | 结果 | 代码 |
|---|---|---|---|
| 阶段聚焦 | 有待办的四段中第一段 | 该段高亮 + 「下一步：…」 | `focusStage()` |
| 点击变形 | 点某一段 | 聚焦到对应屏（Consent / Agents / Outcomes） | `onFocusView` |
| 明暗迁移 | Contrast 按钮 | Canvas 从深色切到纸面（阅读模式），Inspector 保持纸面 | `[data-lf-theme='paper']` 覆盖 |
| 空态引导 | 无编译结果 | 主操作按钮出现在空态卡片里 | Studio 空态 |

> **没有**做自动跳屏。理由：把用户正在阅读的页面从底部换掉是敌意行为；
> "自适应"应该体现在"什么被摆在最显眼的位置"，而不是"页面自己动"。
