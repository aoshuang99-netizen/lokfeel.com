## 一、可操作闭环（已打通）

```
A 撰写中文 → POST /api/im/ai-assist（AI 翻译/建议，零写库）
          → 草稿带六字段溯源 + AI_PRIVATE_DRAFT 来源标注 + 不确定性提示
          → A 审阅/编辑/拒绝
          → authorizeDraftSend() 显式授权（HUMAN_SENT）
          → sendAsUser()（复刻 /api/im/send 幂等语义）→ createMessage 真实落库
          → B 从 DB 读回真实消息（已送达）→ 写已读收据（已读）
```

**零外发三重保障**：
1. AI 草稿 origin 恒 `AI_PRIVATE_DRAFT`，未经 `authorizeDraftSend()` 拿不到发送许可；
2. `/api/im/ai-assist` 只返回草稿，`IMMessage.create` 调用 0、`autoSent:false`、`messageWritten:false`；
3. 云模型默认关闭（`SOCIAL_AI_CLOUD_ASSIST_ENABLED` 未设 → provider=null → 降级草稿，远端调用 0）。

## 五、诚实边界（不可过度声明）

1. **deterministic stub**：AI 翻译用确定性 stub provider 验证编排与契约，**不冒充真实翻译质量**；真实 WorkBuddy 云端算力未在此闭环注入（云开关默认关）。
2. **进程内 + 隔离库**：底层 `createMessage` 链路真实落库，但进程内调用，非 TCP HTTP；HTTP 鉴权/媒体门禁由 route 测试覆盖。
3. **幂等责任在 send route**：底层 `createMessage` 本身不按 clientMsgId 幂等（会抛 P2002）；证明脚本复刻了 `/api/im/send` 的 check-then-create 语义。这是既有架构事实，本轮未改核心写入函数。
4. **150 条冻结双语评测 / 10 人真人盲测**：本轮未做（需 QE 与真人），翻译质量与事实篡改未独立量化。不声称"AI 效果达标"。
5. **非真实双设备**：两个测试账号 + 两个隔离会话，真实 DB 消息；但非两个物理设备/浏览器上下文的 Playwright E2E（Pusher 凭据缺失，生产仍 NOT_TESTED）。
6. **云处理授权**：默认关闭；生产若开启需 Owner 明确授权"私人聊天可送指定云模型"，否则保持关闭。
