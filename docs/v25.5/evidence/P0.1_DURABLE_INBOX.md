## 一、真实缺口与修复

原行为：`payment.failed → payment.succeeded`（同 payment_id）返回 `200 + deferred + ledger_rejected`。
问题：这只能证明"拒绝非法改判"，账本内核把 `CHARGE_FAILED` 设为终态（`FAILED: []`），真实到账的钱**永远结算不了**——静默吞单。

修复：引入 Durable Inbox 状态机，把冲突变成有终态、可恢复、可告警的工作流：

```
RECEIVED ─┬→ APPLIED（常规落账）
          ├→ SETTLED（Provider 确认 paid → 派生新 chargeId 补偿结算）
          ├→ NEEDS_PROVIDER_RECONCILIATION（待权威核验，可恢复）
          ├→ RETRYABLE → DEAD_LETTER（重试耗尽，可追踪）
          └→ REQUIRES_REVIEW（人工复核，绝不误发权益）
```

**先持久化再 ACK**：`receiveEvent()` 以 `deliveryId` 为唯一键先写库；webhook 只有在收件成功后才应回 2xx（杜绝"回 200 但没存下来"）。

**补偿结算原理**：不把 FAILED 款项"改判"成功（那会让重投重复入账），而是新建 `${paymentId}:recovered:${eventId}` 款项承接真实收款，旧失败款项保留为历史。账本 paidTotalCents 只增加一次。
