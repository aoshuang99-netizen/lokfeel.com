## 1. 招募与筛选（10 名真实目标用户）

### 1.1 目标用户定义（人话，不写内部术语）

产品是「把一句话目标摊成能跑的协作方案」的工作区。真实目标用户是**需要推进一件要协调多人的事**的人：
谈渠道合作、招社群成员、办线下活动、做用户调研、给新人配导师。他们不是来看仪表盘的，是来「把事办成」的。

- **核心特征**：近 3 个月内真实推进过至少一个「需要别人配合」的目标；习惯用手机处理工作。
- **非目标用户**：纯前端/后端工程师（会把界面当代码评审）、只看数据的管理者、从未独立推进过协作任务的人。

### 1.2 纳入 / 排除标准

| 项 | 纳入 | 排除 |
|---|---|---|
| 经历 | 近 3 个月推进过合作/招募/活动/调研/带教之一 | 无协作推进经历 |
| 设备 | 日常用智能手机处理工作（iOS/Android 均可） | 仅桌面、拒绝触屏操作 |
| 关系 | 与项目组无直接汇报关系 | 项目组成员、本批开发/测试人员、竞品从业者 |
| 认知 | 能读简体中文、能独立完成 30 分钟会话 | 需要他人代答 |
| 产品熟悉度 | **未用过本产品 V21 工作区**（首次接触） | 已用过 V21 `/workspace` 的人（会污染 5 秒识别） |
| 同意 | 签署知情同意、同意录屏（可面部脱敏） | 不同意录制 |

### 1.3 配额（10 人，分层，避免全是熟人/全是工程师）

| 分层维度 | 配额 |
|---|---|
| 角色：社群/社区运营 | ≥3 |
| 角色：商务/BD/渠道 | ≥2 |
| 角色：中小团队负责人/项目负责人 | ≥2 |
| 角色：其他知识工作者（活动、调研、HR/带教） | ≥2 |

| 性别/年龄段 | 不设硬配额，但记录分布，避免 10 人完全同质 |

### 1.4 筛选问卷（screener，招募时问，不计入测试）

1. 近 3 个月，你有没有独立推进过一件「需要别人配合」的事？（开放描述 → 判定是否纳入）
2. 你平时主要用手机还是电脑处理这类事？
3. 你用过哪些把「目标/任务」拆开的工具？（开放，记录先验心智，不引导）
4. 你之前用过本产品的工作区吗？（用过 → 排除）
5. 是否同意 30 分钟全程录屏 + 录音，且数据仅用于本次可用性评估？
6. 是否需要字号放大 / 读屏 / 高对比等辅助？（用于分层，不影响纳入）

### 1.5 知情同意与合规（Owner 组织时执行）

- 事先书面告知：目的、时长（≤30 分钟）、录制范围、可随时中止且不影响补偿、数据留存期、联系人。
- PII 与业务数据分离：录屏里的账号用**隔离夹具账号**，不得出现真实客户/真实成员数据。
- 原始证据按 §7 命名与留存；对外报告只用编号（P01…P10），不出现姓名/联系方式。
- 补偿由 Owner 按当地规范发放，与「是否通过/是否说好话」无关。

## 3. 任务脚本

### 通用规则（主持人必须遵守）

- 一次只念一个任务，**念完不再解释**；用户提问统一回「你按自己的理解试试」。
- 不提示按钮位置、不替用户点击、不用「你应该点这里」。
- 每任务设时间盒；超时记为「未完成（超时）」，记录卡在哪一步、为什么。
- 全程 think-aloud；记录员记原话（尤其是误解），不改写。

### 3.1 首屏 5 秒识别（不干预，先做，在做任何任务之前）

1. 打开 `/workspace` 的「开始」屏，**展示 5 秒**后收起（遮住/切空白）。
2. 立即问三题（原话记录）：
   - Q1 你觉得这个产品是做什么的？给谁用？
   - Q2 第一屏让你做的第一件事是什么？
   - Q3 你记得屏幕上有哪些词？（不要求准确，测的是「人话 vs 工程噪声」）
3. **判分口径（先定，不事后放宽）**：
   - 「理解正确」= Q1 说出「把目标/要做的事写下来，系统帮拆成可推进的方案/任务」这类意思（提到协作/推进/任务均可），**且** Q2 指向「写下目标 / 输入框 / 开始」。
   - Q3 若出现 `/api/`、`GET`、`未就绪 ×4`、接口路径等工程噪声 → 记为「首屏工程噪声」缺陷（与 `workspace-now.spec.ts` 的可见文本断言同源），**不计为理解正确**。

### 3.2 主任务链（指定任务，顺序执行）

| 编号 | 念给用户的指令（原话） | 起点 | 成功判据 | 时间盒 |
|---|---|---|---|---|
| **T1 写下目标** | 「假设你两周内要约 10 位目标用户做深度访谈，我们提供产品内测名额作为对价。请把这件事告诉这个产品。」 | 开始屏 | 在输入框写下含「目标/期限/对价」的一句话并点「开始」，出现「理解卡/方案」，且**不跳屏** | 3 min |
| **T2 编辑方案** | 「看一下它给你摊出来的方案。里面如果有你想改的地方（比如期限、判据、对价），试着改一处并保存。」 | 上一步结果态 / 任务详情方案区 | 找到方案编辑入口并完成一次字段修改 + 保存；若产品当前不支持字段级编辑，如实记「不可编辑/未找到」，**不得代填成功** | 4 min |
| **T3 找到任务** | 「你交代过的事，去把它找出来，看看现在到哪一步了。」 | 任意屏 | 进入「任务」屏，打开某条任务详情（看到标题/状态/判据） | 3 min |
| **T4 查看执行证据** | 「看看这件事到底做到哪一步了，有没有真正的执行记录或证据。」 | 任务详情 | 在详情里找到 execution-panel / 方案版本 / 运行阶段，并说出「这是已执行 / 待批 / 无关联运行」中的真实状态（以界面为准） | 4 min |

> T2 说明：V21 第二批已交付字段级编辑（`spec-editor` / `mission-spec-section`）。若夹具任务无 spec，
> T2 在「开始屏结果态」或「有 spec 的任务详情」上执行；组织者需预先确认哪个入口可用，并在记录表写明。
> 不可用则逐人记 BLOCKED，**不为了凑完成率而伪造**。

### 3.3 事后访谈（任务全部结束后）

- 开放问题 3 题：① 哪一刻你最不确定在干什么？② 哪个词最不像人话？③ 如果明天还用，你会先点哪里？
- 可选 SUS（10 题，5 点量表）作为**补充描述**，不作为 G04 主口径（见 §4）。
- 记录「是否愿意再用」及理由。

## 4. 成功口径（G04 门槛）

### 4.1 主口径（唯一判定口径）

> **≥8 / 10 名受试者「能理解产品」并「完成首屏任务」。**

拆成两个**都必须满足**的条件，逐人判定，先定规则不事后改：

| 条件 | 判定 |
|---|---|
| A. 理解产品 | §3.1 的「理解正确」= 真 |
| B. 完成首屏任务 | T1 成功判据达成（写下目标 → 出现方案 → 不跳屏） |

- 单人「通过」= A ∧ B。
- G04 达标 = 通过人数 ≥ 8（10 人中）。
- **只写「完成 T1」不算通过**（可能是照着念、并不理解）；只写「理解」也不算。

### 4.2 次级指标（描述用，不替代主口径）

| 指标 | 口径 |
|---|---|
| 首屏 5 秒识别正确率 | A 为真的比例，附 95% CI |
| T1–T4 逐任务完成率 | 各任务成功人数 / 10，含超时/求助拆分 |
| 逐任务耗时 | 中位数 + 范围（min–max），不报均值掩盖离群 |
| 求助/卡点次数 | 每任务记录「主持人是否介入」「卡在哪一步」 |
| 工程噪声命中 | Q3 出现接口/调试词的人数 |
| 首屏任务首次点击正确率 | 第一次操作是否直接落到输入框 |

### 4.3 什么情况下不判通过（诚实条款）

- 通过人数 < 8 → **不通过**，如实写差多少。
- 任一受试者数据缺失/录制失败且未事先定剔除规则 → 该人记「数据不完整」，**不算通过、也不擅自剔除**；有效样本 <10 时，达标线按「≥8 且比例 ≥0.8」重算并在报告写清，不得默默按 8/8 算。
- 夹具缺任务导致 T3/T4 大面积 BLOCKED → 报告写「环境阻断」，不得把 BLOCKED 记成「完成」。
- 主持人出现过提示操作 → 该人该任务记「受提示完成」，单列，不并入通过数。

## 6. 统计方法（先定，避免事后挑好看的算）

1. **主口径**：二项比例。报告 `k/10` 通过人数与点估计 `p̂ = k/10`。
2. **区间**：给 **95% Wilson 置信区间**（小样本 n=10 不用 Wald 正态近似）；结论以「点估计是否 ≥0.8 且 k≥8」为准，区间仅作不确定性说明，**不拿区间下限当达标线、也不拿上限当达标**。
3. **精确性**：附 `P(X ≥ 8 | n=10)` 在 `p=0.8` 下的二项概率作参考，说明「10 人样本」的判别力有限，不夸大统计显著性。
4. **描述统计**：耗时/求助次数用**中位数 + 范围**；逐任务完成率用频数/10；不用均值掩盖离群。
5. **定性资料**：Q1–Q3、卡点原话做主题归类（两名记录员各自编码，不一致处标「分歧」保留，不强求一致）。
6. **不做的事**：不做 p 值择优、不剔除「说得不好听」的受试者、不把 SUS 折算成通过人数、不把自动化脚本结果并入真人样本。
7. **剔除规则（先定）**：仅当①录制全程失败且无记录表、或②受试者主动中止，才记「数据不完整」；即便如此也保留在分母并单列，不静默删除。

## 7. 证据命名规范

### 7.1 目录

```
docs/v21/batch2/usability/            # 汇总与 manifest（本批只建规范，不预造数据）
docs/v21/batch2/usability/raw/        # 原始录屏/录音（Owner 组织时产出，默认 .gitignore 或受控留存）
docs/v21/batch2/usability/records/    # 逐人记录表（§5 模板填充）
```

### 7.2 文件名模板

```
G04_<YYYYMMDD>_P<NN>_<session>_<type>_<seq>.<ext>
```

| 段 | 取值 | 例 |
|---|---|---|
| `<YYYYMMDD>` | 会话日期 | `20261120` |
| `P<NN>` | 受试者编号 `P01`…`P10` | `P03` |
| `<session>` | 会话序号/场次 | `S1` |
| `<type>` | `screen`(录屏) / `audio`(录音) / `record`(记录表) / `consent`(同意书) / `5s`(首屏识别) / `sus` | `screen` |
| `<seq>` | 同类型序号，3 位 | `001` |
| `<ext>` | `mp4` / `m4a` / `md` / `pdf` | `mp4` |

示例：`G04_20261120_P03_S1_screen_001.mp4`、`G04_20261120_P03_S1_record_001.md`。

### 7.3 汇总文件

- `usability/manifest.csv`：一行一个证据文件，列 `file,participant,type,sha256,capturedAt,consentRef,retentionUntil`。
- `usability/G04_RESULT.md`：**由 Owner/验收人**填写 `通过人数 / 结论 / 署名 / 日期`，并引用原始证据清单。
- 校验：每个 `record` 必须有对应 `consent` 与 `screen`；缺一在 manifest 标 `incomplete`，不并入统计。

### 7.4 留存与脱敏

- 原始录屏默认留存至 Owner 指定期限（建议 ≤90 天），到期销毁并在 manifest 记录销毁日期。
- 对外/入仓报告只用 `P<NN>` 编号；录屏中出现的账号一律为隔离夹具账号。
- **本批不生成任何上述 raw/records 文件**（无真人会话）；只交付本规范与模板。
