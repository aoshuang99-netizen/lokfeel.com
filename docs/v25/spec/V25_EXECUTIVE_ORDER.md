# LokFeel V25｜开源生成式 AI 社交平台战略重构

这次需要把定位提升一个层级：

LokFeel 不只是一款 AI 社交应用，而是一个同时服务个人、企业和开发者的开源生成式 AI 社交平台。

它既要有能够直接挑战传统聊天体验的消费端产品，也要有让企业搭建自己 AI 社交网络的 SaaS 平台，还要开放模型、协议、SDK、Agent 和插件能力，让第三方共同建设生态。

建议的统一战略定位

# LokFeel — Open AI Social Platform

以人类意图和关系智能为核心，以隐私自主权为基础，通过开放生成式 AI、可信通信和智能体协作，连接个人、企业与开发者。

一个平台、两类核心客户、三种产品形态、一个开放生态。

## 一、完整的产品与平台关系

LokFeel Open AI Social Platform

统一身份、关系智能、生成式 AI、隐私与开放协议

LokFeel Personal

私人 AI、聊天、关系记忆、朋友与社群、跨语言沟通

LokFeel Business

企业社区、内部协同、伙伴网络、Agent、私有部署

LokFeel AI Platform & Developer Ecosystem

模型与 Social MoE

Agent / Skill SDK

开放消息与社交协议

隐私、授权、关系图谱

API / MCP / A2A

开源社区与插件市场

第三种产品形态就是 LokFeel Community / Self-hosted：个人开发者、开源社区和企业可使用同一核心代码自行部署社交空间，再按需连接 LokFeel Cloud 或其他模型服务。

这与 HAI/ONE 的关系也需要锁死：HAI/ONE 提供可复用的人本智能能力与科研方法；LokFeel 负责社交领域的产品、开放协议、社会关系模型和生态。 LokFeel 不必复制整个 Emory OS，但可以复用 ODC 授权、QE 路由、VAL 独立核验、OIG 记忆证据图和 VEC 能力演进。

## 二、个人与企业不是两个割裂的平台

| 维度     | Personal：个人用户                   | Business：企业用户                                      |
| ------ | ------------------------------- | -------------------------------------------------- |
| 第一需求   | 更好地理解、联系、沟通和维系关系                | 让员工、客户、伙伴和社群更高效可信地协同                               |
| 主要入口   | Chats / People / Spaces / My AI | Spaces / Members / Connections / Agents / Insights |
| 生成式 AI | 私人沟通助手、翻译、语境理解、内容生成             | 组织知识助手、客户/伙伴沟通、会议和社区 Agent                         |
| 关系智能   | 自己的关系记忆、共同约定、沟通偏好               | 获授权的组织关系图谱、合作意向、社群互动                               |
| 权限     | 用户控制个人与共享信息                     | 组织 RBAC + 成员个人隐私边界                                 |
| 部署方式   | 云服务 + 逐步增加端侧处理                  | SaaS、多租户隔离、专属实例或自行部署                               |
| 商业模式   | 免费基础通信 + 可选 AI 服务             | 按席位、组织规模、AI 用量与部署服务组合收费                            |

最重要的设计规则：企业购买了 LokFeel，也不能因此拥有员工的私人关系记忆。 个人身份与组织身份可以关联，但数据密钥、授权、存储和查询范围必须隔离。管理员只能访问组织有权处理的数据。

## 三、真正的开放平台，而不只是 GitHub 放一份源码

我建议采用 Open Core + 可自托管发行版 + 商业云服务，并把是否真正开源写进许可证，而不是只把仓库设为公开。

| 层级                           | 开放策略                           | 目标                             |
| ---------------------------- | ------------------------------ | ------------------------------ |
| 协议与 Schema                   | 开放标准/公开规范                      | 允许别人实现兼容的客户端和服务                |
| 消息与 Social SDK               | 优先 Apache-2.0 或其他经审查的 OSI 开源许可 | 开发者可以构建独立社交应用                  |
| Consent、Memory、Social Router | 开源可审计核心实现                      | 让用户和企业能够验证数据使用边界               |
| 自托管 Community Edition        | 具有真实可运行的开源功能                   | 不购买 LokFeel Cloud 也能通信、管理私有 AI |
| 模型适配器与评测集                    | 开源代码；模型权重和数据逐项明确许可             | 支持本地、第三方和自研模型                  |
| LokFeel Cloud / Enterprise   | 商业托管、SLA、专业运维及增值能力             | 形成持续收入，支持开源生态                  |

开源软件、开放权重和开放协议是三件不同的事。模型允许下载不代表允许任何商业用途；源码可见也不代表真正开源。

例如，Dify 的公开许可证对多租户服务有额外限制，因此不能未经许可直接把它作为 LokFeel 多租户商业平台的核心发行代码。

需要避免两种失败：一种是把所有差异化能力封闭起来，最终没人愿意参与生态；另一种是过早承担全栈开源维护成本，却没有付费用户和可持续商业模式。

## 四、技术架构：把开源 AI 真正变成社交基础设施

应用层｜Personal · Business · Community

Web / iOS / Android / Desktop / 企业控制台

社交网络层｜Open Social Core

真实身份 · 聊天 · 联系人 · 关系图谱 · 群组 · 企业组织

生成式智能层｜Social AI Engine

意图理解 · 情境记忆 · 专家路由 · 多语言生成 · Agent

开放生态层｜Protocols & SDK

开放通信 · MCP · A2A · 模型适配器 · Skills · 插件

可信基础层｜Privacy · Consent · Evidence

私有记忆库 · E2EE · 授权控制 · 审计 · 独立核验

### 2026 年值得采用的开放技术

| 开源项目 / 标准                                                                                                                                       | LokFeel 应如何使用          | 重要边界                     |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------ |
| Matrix / Matrix Rust SDK                                                | 评估作为开放通信、群组和联邦底座       | 优先做 PoC，不必立刻替换已开发的聊天模块   |
| AT Protocol                                                                 | 公开身份、公开社交内容及关系可移植性研究   | 不替代私密聊天加密                |
| MCP                                                                                   | 为企业和个人提供经授权的工具、数据及服务连接 | 每个工具调用仍需权限判断             |
| A2A                                                                                 | 跨组织、跨厂商 Agent 协同       | Agent 之间通信不代表获得真人授权      |
| LiveKit                                                                            | 音视频通信、实时多模态 AI         | 不可仅因使用 WebRTC 就宣称端到端加密完整 |
| vLLM / llama.cpp                                                                 | 云端高吞吐与本地模型推理           | 模型权重许可、硬件和部署分别审核         |

这些技术已有可核验的公开实现。Matrix SDK 提供通信与加密相关能力；A2A 面向智能体互操作；MCP 的 2026 年规范强化了授权与协议扩展。

尤其值得对标 MindRoom：它已经采用 Matrix、可替换的本地/云模型及共享 Agent，支持自行部署。这说明基础组合并非无人涉足。LokFeel 必须在个人—企业关系上下文、细粒度双向授权、社交理解效果以及可信数据治理上形成真正差异化。

## 五、AI 模型的战略：开源生成平台先行，真正 MoE 并行科研

2026 年的 SMMU 研究显示，先进多模态模型在长时间跨度的社会关系理解上仍明显落后于人类。微软研究团队在 2026 年发表的 AIM 预印本则展示了多用户私有与共享记忆的架构思路，同时其严格记忆操作准确率远非完美。

这两项研究提示我们：真正的差异化不只是模型更大，而是理解、记忆、授权和纠错四种能力一起进步。

| 路线                         | 当前应做什么                        | 是否阻断首版上线           |
| -------------------------- | ----------------------------- | ------------------ |
| 多模型生成式平台                   | 支持本地模型、开源权重和商业云模型的统一 Adapter  | 是，至少有两种真实可替换后端     |
| Social Intelligence Router | 按意图、隐私、风险、质量及成本选择处理路径         | 是，先用规则 + 检索 + 现有模型 |
| 用户/企业关系记忆                   | 权限范围内的动态上下文与持久事实              | 是，必须有纠错、撤回、隔离      |
| 社会智能专用模型                   | 长程关系理解、跨文化语境、群体协调微调           | 否，可并行试验            |
| 稀疏神经 MoE                   | 同预算比较小模型、RAG、专家路由与 Sparse MoE | 否，实验成功再部署          |
| VEC 自我进化                   | 从经许可的失败案例产生候选技能并独立评测          | 否，研究层不得自行发布模型      |

这使 LokFeel 可以先成为一个有用、可自托管、可扩展的开放生成式 AI 平台，再逐步拥有自己的社会智能模型，而不是等待一个尚未训练成功的模型才能发布社交产品。

所有试点人数、产品时间节点和商业目标都是建议规划，不代表已有客户或已完成实验。

# LOKFEEL V25 — Open Generative AI Social Platform 执行总令

本轮以 V25 战略与技术计划书为唯一新需求源，同时继承 V21–V24 所有真实已实现代码、测试与安全门禁。不得重置历史证据或擅自改变生产状态。

## 唯一总目标

建设同时服务 Personal 与 Business 的开源生成式 AI 社交平台，具备真实通信、关系智能、私有和共享记忆、双向授权、企业隔离、模型自由选择、开放 SDK、自托管发行版与可扩展 Agent 生态。

## 立即并行执行

**A. 产品与源码事实组**

完成当前生产、远端、本地 SHA 和 Payment 风险复核；扫描 Chat、Match、Relation、Agent、Consent、Memory、Billing。给每个模块 REUSE / ADAPT / BUILD / DEPRECATE 结论，不得重复发明已有功能。

**B. Personal 产品组**

完成 Chats、People、Spaces、My AI 的真实功能映射与交互设计，以个人 AI、可信关系及双向通信为主，不以普通 Agent 任务页做首页。

**C. Business 产品组**

完成组织、成员、社群空间、跨语言协同、AI 关系助手、企业管理员与私有数据隔离。组织权限不得继承个人私有记忆访问权。

**D. Open Source 平台组**

完成 License RFC、Community Edition、自托管部署、API/SDK、模型 Adapter、开放协议 PoC 和贡献安全流程。社区版本必须真实可运行，不得依赖隐藏商业密钥。

**E. AI 与模型研发组**

完成 Social Intelligence Router 的最小真实实现，并独立建立长期社会语境、隐私泄露、情绪误判和跨语言评测。Sparse MoE 进入等预算科研，不作为首版发布前置依赖。

**F. 独立验收与发布组**

按 29 张任务卡检查源码、真实 API、两端消息、权限、群组、模型来源、真实用户体验、性能、License 和 SBOM。未获批准不得执行生产迁移、扣款、对外消息或正式发布。

## 验收铁律

- 个人与企业必须共用经过版本化的开放核心，而不是两套互不兼容产品。
- 私密信息跨主体、跨租户、跨模型处理的未授权泄漏必须为零。
- AI 生成内容不得冒充真人发言。
- 只有真实消息与参与者确认才能升级相应业务状态。
- 自托管社区版必须通过两套独立干净环境的安装和核心功能验证。
- 代码通过测试不等于独立审查，更不等于生产已部署。
- 所有功能必须绑定 SHA、真实证据、失败负例、独立审查人与验收状态。

**本轮成果应是可运行的开放生成式社交基础设施与可验证的个人、企业业务闭环，不是再次改出一套静态 AI SaaS 界面。**

立即执行任务 `V25-00` 至 `V25-14` 的无授权依赖部分；其他协议、生态和模型科研按任务依赖并行推进，直到真实工程阻断点出现。

最终应坚持一个判断：LokFeel 的商业产品与开源平台要相互增强，而不是相互争夺资源。 个人用户提供真实场景与需求，企业用户提供组织化应用和商业收入，开发者贡献模型、协议与扩展能力；平台在得到明确许可的前提下从真实反馈中持续改进。

这才有机会形成一个不同于微信、WhatsApp、LINE，也不同于普通 AI Agent SaaS 的开放生成式社交生态。
