系统架构总图
图 1.1 — LokFeel v2.0 整体系统架构（分层视图）
架构说明：Next.js 15 App Router 统一全栈，Admin 与 App Frontend 共享 Prisma Client。Route Handlers（~180端点）经 Auth Middleware 和 Zod 验证后调用 6 大 Service 层，Prisma 7 连接 Neon PostgreSQL（~46表），Redis 提供实时缓存和 SSE PubSub，外部 AI/支付/社媒 API 通过封装服务接入。
2
模块交互关系图
图 2.1 — 8大模块交互关系（请求/响应/事件流）
交互说明：Admin Dashboard 是全局路由中枢，8个子模块通过 Redis PubSub 事件总线通信。核心事件流：用户注册触发 Bot 分配和匹配引擎初始化 → 匹配成功触发 VIP 资格评估和 Bot 行为学习 → 付费成功触发 VIP 升级通知 → 举报新增触发 AI 客服工单创建和安全审核流程。所有事件异步写入分析数据库，供数据分析模块实时聚合。
3
前端 ↔ 后端 API 交互图
图 3.1 — 典型页面请求/响应生命周期（GET列表 + SSE实时告警 + 写操作）
实时告警机制（SSE）：前端通过 `new EventSource('/api/admin/alerts/stream')` 建立持久连接，后端通过 Redis PubSub 订阅 Bot 异常（拒绝率>80%）、举报积压（>10条）、支付失败等事件通道，实时推送告警卡片到 Admin Dashboard，无需轮询，延迟 <500ms。SSE 连接在页面卸载时自动关闭，重连逻辑内置指数退避。

数据流 & 数据库 ER 关系图
图 4.1 — 核心数据实体关系（v2.0 新增表高亮标识）
ER图说明：v2.0新增17张表，分属三个新模块（AI推广图4张：CreativeTemplate/CreativeJob/CreativeAsset/ABTest；AI客服4张：SupportTemplate/KnowledgeArticle/SupportTicket/SupportTicketNote；VIP收件箱3张：VIPMembership/VIPMessage/VIPServiceRecord）。User表为所有模块的核心锚点，付费成功事件触发VIPMembership的1:1创建，AI客服通过SupportTemplate.triggerKeywords → SupportTicket.category路由。

5.5 核心结论

✅ 可行 — 核心路径
  • v1.0 已验证基础架构，v2.0 是增量扩展而非重构
  • P0（4个核心模块）的工程量约占整体 40%，风险可控
  • Prisma + Neon + NextAuth 技术栈已熟悉，开发效率有保障
  • Stripe webhook 已在 v1.0 验证，支付模块无额外风险
  • 新模块（AI推广图/AI客服/VIP）与现有表通过外键自然关联
⚠️ 风险 — 需分阶段管控
  • AI API 成本需严格管控（建议设置 $50/月上限熔断器）
  • 6 周周期偏长，建议砍掉 Week 11-12 的 P2 内容专注 P0/P1
  • 向量检索（embedding）需额外学习成本，预留 2-3 天 POC
  • SSE 实时告警建议先用 Polling（5s 轮询）替代，后期升级 SSE
  • Reddit/Twitter API 自动化发布需账号白名单 + 人工二次确认
⚡ Scout 最终评估：v2.0 技术上完全可行，但 scope 过大（200+四级功能）。建议分两期交付：第一期（Week 7-9）聚焦 P0 核心（全局监控 + 用户管理 + 安全审核 + 匹配引擎），第二期（Week 10-11）交付 P1（支付订阅 + AI推广图 + AI客服 + VIP收件箱）。砍掉所有 P2 功能（Bot系统、内容管理移到 Phase 5）。核心原则：先跑通，再丰富，绝不在 Day 30 止损节点前押注 P2 功能。
